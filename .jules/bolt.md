## 2026-10-04 - V8 Map performance for numeric string keys & Geometry reading order
**Learning:** Replacing ES6 `Map` with plain JS objects `{}` inside inner loops (e.g. sequence matching algorithm) surprisingly degraded performance in V8 for numeric string keys (~40% slowdown). On the other hand, pre-grouping linear collections in nested search loops (e.g. `mangaGeometryOrder` grouping bubbles per panel) reduced emission pass complexity from O(P * B) to O(B), resulting in a ~55% execution time reduction (4.38s -> 1.91s / 10k iterations). Early bounding box disjoint checks in geometry functions (`intersectionOverArea`) provided an additional ~45% speedup on disjoint box pairs.
**Action:** Benchmark dynamic key structures in V8 before replacing `Map` with plain objects. For spatial and geometry matching operations, short-circuit disjoint bounding boxes early and pre-group relations to avoid nested iteration across disjoint box sets.

## 2026-10-28 - Pre-compiled queries & .pluck() overhead reduction
**Learning:** Re-compiling a prepared statement inside a frequently hit Express route (`db.prepare(...)`) introduces unnecessary overhead. Furthermore, `better-sqlite3` creates intermediate JavaScript objects when using `.all().map()`.
**Action:** When extracting a single column from all rows, hoist `db.prepare(...).pluck()` outside the route handler. Calling `.all()` on this pre-compiled, pluck-configured statement returns a direct array of primitives, bypassing mapping and significant garbage collection overhead.
